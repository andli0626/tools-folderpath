目前只有 macOS 版本：dmg 与 zip 都是 Universal 通用包，Apple Silicon 与 Intel 用的是同一个文件。下载链接与页面同源，不经过 Release 附件与任何第三方域名。

dmg 里有什么

两个独立 app，bundle id 不同，自动化授权也各自独立；工具栏按钮是一次性进程，点完即退。

CopyPath_1.3.0_universal.dmg ├── CopyPath.app 主程序 · 托盘 / 快捷键 / 悬浮按钮 ├── CopyPath Toolbar.app 访达工具栏 helper └── Applications → /Applications 软链接，拖过去即安装

平台支持：只有 macOS

macOS 12.0 及以上，Intel 与 Apple Silicon 共用同一个 Universal 包。

  • macOS：完整功能 —— 快捷键、托盘、访达工具栏、悬浮按钮
  • Windows：暂不提供。取路径依赖访达 AppleScript，悬浮按钮是 AppKit 的 NSPanel，换个打包目标产不出能用的 app
  • Linux：同样不在当前支持范围

要支持 Windows，需要另写取路径与悬浮窗两套实现，属于独立工程，不是补一个下载按钮。

核心能力

它只做一件事，但把这件事做干净

取路径、写剪贴板、弹通知。没有多余的窗口、没有后台服务、没有需要登录的云。

01 / 触发

四种触发，哪个顺手用哪个

快捷键、菜单栏、访达工具栏、屏幕悬浮按钮接入同一套语义，复制结果完全一致。

  • ⌃⌥⌘P 不用切窗口，复制「所在文件夹」
  • 托盘菜单里还有「复制选中项自身路径」与最近 10 条历史
  • 悬浮按钮点击不激活 CopyPath，访达保持前置
02 / 语义

路径语义只有一种解释

选中项优先，没有选中项就回退到前置窗口目录。多选时每行一条，同目录自动去重。

  • 「文件夹」段：文件取所在目录，文件夹取自身
  • 「文件」段：只取文件本身，全选文件夹时回退窗口目录
  • 不会把桌面当成「没有窗口」的答案
03 / 可靠

取不到就明说，不乱写剪贴板

没有访达窗口、脚本失败、权限没给，都算失败：剪贴板保持原样，只弹一条失败提示。

  • 不会把旧值覆盖成一个看起来对的错路径
  • 通知失败不影响已写入的剪贴板
  • 单实例锁：重复启动会被挡掉，不会起两个托盘
04 / 原生

原生实现，轻、稳、不抢焦点

Rust + Tauri v2，没有 Web 前端；悬浮按钮是原生 NSPanel，不是网页浮层。

  • macOS 26+ 用原生 Liquid Glass，10.14–25 用 vibrancy，12–13 回落深色实底
  • 任何壁纸上文字都清晰，浅色底不再「隐形」
  • 全站只有一条 osascript 读访达，路径不出本机

为什么左键不直接复制？ 挂了菜单的菜单栏图标会在按下时自己弹菜单，事件覆盖层收不到左键 —— 「左键一键复制」和「右键出菜单」在同一个图标上无法兼得。所以一键动作交给了全局快捷键与悬浮按钮，托盘只负责出菜单。

路径语义

复制的永远是「你以为的那个路径」

选中项优先，没有选中项时回退到前置窗口目录。多选时剪贴板里每行一个路径，同一目录自动去重。

选中 1 个文件它所在的目录该文件自身该文件自身

安装

3 分钟装好，之后不用再管

没有安装器、没有后台服务。dmg 挂载、拖进应用程序、授权一次，就结束了。

1

下载并拖进「应用程序」

双击 dmg 挂载，把 CopyPath.app 拖到 Applications。想用工具栏按钮，就把 CopyPath Toolbar.app 一并拖过去。

CopyPath_1.3.0_universal.dmg
2

首次打开并授权

右键 → 打开 → 再点「打开」过掉 Gatekeeper。第一次触发时系统会问访达自动化权限，允许即可；工具栏按钮是独立 bundle id，需要单独授权一次。

系统设置 → 隐私与安全性 → 自动化
3

验证一下

在访达选中一个文件，按下快捷键，然后在终端里把剪贴板打出来核对。结果对得上就装好了。

pbpaste

装到内部盘

开机自启会把 .app 的绝对路径写死。放在外置盘时，开机若盘没挂载，自启会静默失效；建议装在内部盘的「应用程序」。

开机自启

托盘菜单 → 「开机自启」勾选即可，写入 ~/Library/LaunchAgents/CopyPath.plist，不需要额外工具。

卸载

托盘退出后删掉两个 .app；开过自启再删 LaunchAgent。数据可留在 ~/Library/Application Support/com.lilin.folderpath/。

使用手册

四个场景，照着做就行

安装、悬浮按钮、工具栏按钮、卸载 —— 每件事都只有几步，做完有明确的成功判据。

安装与首次授权

从下载到第一次成功复制，共四步。

步骤
  1. 下载 dmg，双击挂载，把两个 app 拖进 Applications。
  2. 右键 CopyPath.app → 打开 → 再点「打开」。
  3. 按一次快捷键，系统弹自动化授权，允许访问「访达」。
  4. 终端执行 pbpaste 核对结果。
提醒
  • 首次授权只问一次，之后不再弹。
  • 工具栏按钮需要单独授权一次。
  • 拒绝授权后，复制会失败且不动剪贴板。

悬浮按钮怎么用

默认显示在主屏右缘居中。

步骤
  1. 左段点一下：复制文件夹路径。
  2. 中段点一下：复制文件路径。
  3. 右端 ×：立即隐藏；右键可切换三种语义。
  4. 按住任意段拖动，松手即记忆位置。
提醒
  • 点击不会激活 CopyPath，访达保持前置。
  • 拖动越出屏幕会被自动拉回可见区。
  • 删掉 float-button.json 重启即回默认位置。

访达工具栏按钮

把 CopyPath Toolbar.app 放到工具栏上。

步骤
  1. 确认 CopyPath Toolbar.app 在 Applications。
  2. 在访达里选中它，按住 ⌘ 拖到工具栏。
  3. 打开任意访达窗口，点它一次。
  4. 允许自动化授权，再点一次验证。
提醒
  • 按钮绑定的是拖入时的 .app 路径。
  • 重装或挪动后需重新拖入一次。
  • 移除时按住 ⌘ 把按钮拖出工具栏。

卸载与数据位置

删干净，不留后台残留。

步骤
  1. 托盘菜单 → 「退出 CopyPath」。
  2. 删除 CopyPath.app 与 CopyPath Toolbar.app。
  3. 开过自启就删除 CopyPath.plist。
  4. 可选：删除 Application Support 下的数据目录。
数据在哪
  • 最近路径：history.json（上限 10 条）
  • 悬浮按钮：float-button.json
  • 单实例锁：instance.lock
  • 自启：LaunchAgents/CopyPath.plist

常见问题

遇到问题，先看这里

大多是权限与路径绑定两件事。按下面的判据逐条核对，比重新安装更快。

提示「未获得授权」或报错 -1743
重新打包会用 ad-hoc 重新签名，cdhash 变了，旧的自动化授权随之失效。重置后重新授权一次即可： tccutil reset AppleEvents com.lilin.folderpath tccutil reset AppleEvents com.lilin.folderpath.toolbar 工具栏按钮是独立 bundle id，需要单独重置。
访达工具栏按钮点了没反应
按钮绑定的是拖入时的 .app 路径。重新打包后旧路径失效，把 Applications 里的 CopyPath Toolbar.app 重新 ⌘ 拖入一次即可。另一种可能是首次点击的授权弹窗还没允许。
提示「没有打开的访达窗口」
脚本刻意不使用 insertion location —— 0 个窗口时它会静默返回桌面，是个错答案。所以没有窗口就是失败：剪贴板保持原样，只弹失败提示。
快捷键没反应
多半被别的应用占用了。注册失败只在 stderr 打日志并降级，托盘菜单与悬浮按钮仍然可用。需要换键时，改源码里的 SHORTCUT 常量后重新打包。
托盘图标不见了，或者起了两个
先在终端执行 pgrep -x copypath 看进程。重复启动会被单实例锁挡掉并打印提示，不会真的起两个；若图标不见，确认菜单栏没有被刘海或其它工具挤掉。
悬浮按钮不见了，或者拖到屏幕外面了
托盘菜单 →「悬浮按钮」勾选即可显隐。位置与开关存在 Application Support/com.lilin.folderpath/float-button.json，删掉该文件重启即回到默认（显示、右缘居中）。运行中拖出屏幕不会被自动找回，用开关关掉再开会复位。
通知不弹
到系统设置 → 通知里确认「CopyPath」允许通知。通知只是反馈，复制本身已经成功，pbpaste 能看到结果。
能复制文件夹里的多个文件吗？顺序固定吗？
可以。多选时剪贴板里每行一个路径，同一目录下的多个文件会去重成一行；顺序以访达返回为准。需要严格顺序时，建议逐个复制或直接写脚本。
