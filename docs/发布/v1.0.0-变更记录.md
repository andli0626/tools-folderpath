验证到什么程度。当前用法与故障排查请看根目录 [README.md](../../README.md)。

- 版本：1.0.0
- 日期：2026-09-22

## 二、应用改名 FolderPath → CopyPath

### 2.1 逐文件清单

| 文件 | 改了什么 |
| --- | --- |
| `src-tauri/tauri.conf.json` | `productName`: `FolderPath` → `CopyPath`；新增 `version: "1.0.0"` |
| `src-tauri/Cargo.toml` | `[package] name`: `folderpath` → `copypath`；`[lib] name` → `copypath_lib`；`description` 改为 CopyPath 开头 |
| `src-tauri/Info.plist` | `CFBundleName`、`CFBundleDisplayName` → `CopyPath`；`CFBundleExecutable` 与二进制名保持一致（`copypath`）；`NSAppleEventsUsageDescription` 主语改为 CopyPath |
| `src-tauri/src/main.rs` | 调用点改为 `copypath_lib::{probe,run}`；重复启动提示改为「CopyPath 已经在运行…」 |
| `src-tauri/src/lib.rs` | 启动失败 panic 文案改为「运行 CopyPath 失败」 |
| `src-tauri/src/tray.rs` | 退出项 → 「退出 CopyPath」；tooltip → 「CopyPath · 点击展开菜单，全局快捷键 ⌃⌥⌘P 直接复制」 |
| `src-tauri/src/notify.rs` | 通知 `appname("CopyPath")` |
| `dist/index.html` | 占位页标题与文案 |
| `build-app.sh` | `APP_NAME="CopyPath"`、`EXE_NAME="copypath"` |
| `README.md` | 全文改写 |

### 2.2 刻意**没有**改的部分

这几处保留 folderpath 字样是设计决定，不是漏改：

| 保留项 | 位置 | 理由 |
| --- | --- | --- |
| `com.lilin.folderpath` | `tauri.conf.json` / `Info.plist` / `main.rs` 的 `config_dir()` | **bundle id 是单向门**。改了会导致：① 已授予的「自动化」权限失效，要重新授权；② 历史数据目录 `~/Library/Application Support/com.lilin.folderpath` 变成孤儿。改名只动显示名。 |
| `__FOLDERPATH_NO_WINDOW__` | `finder.rs` 的 `NO_WINDOW_MARK` 与 AppleScript 哨兵串 | 纯内部协议字符串，Rust 侧靠它匹配 stderr 判定「无窗口」，改了无收益。 |
| `Mode::FolderPath` | `finder.rs` 枚举变体，被多处单测引用 | Rust 内部标识符，不面向用户。 |
| `/Users/lilin/cargo-target/tools-folderpath` | `build-app.sh` 的 `CARGO_TARGET_DIR` | 构建缓存目录，与产品名无关；换名会白白重编全部依赖。 |

### 2.3 改名带来的连带影响（踩过的坑）

1. **二进制名变了，旧进程杀不掉。** `build-app.sh` 用 `pkill -x "$EXE_NAME"` 停旧实例，改名后
   `copypath` 匹配不到仍在运行的 `folderpath` 进程；旧进程持有单实例文件锁，新实例启动即退出，
   表现为「打包成功但应用没起来」。本轮手工 `pkill -x folderpath` 解决，**没有**把旧名字写进脚本
   （一次性迁移的残留会长期误导后来人）。
2. **LaunchAgent 名称变化。** 开机自启的 plist 由 `tauri-plugin-autostart` 按显示名生成，
   从 `FolderPath.plist` 变为 `CopyPath.plist`。脚本在装新包时会同时
   `rm -rf` 掉 `~/Applications/FolderPath.app` 与 `CopyPath.app` 再放入新包，避免两个托盘图标。
3. **必须装在内部盘的 `~/Applications`**，不能留在 `/Volumes/SanDis1TB` 外置盘：LaunchAgent 会把
   `.app` 绝对路径写死，开机时盘未挂载则自启静默失效。

## 三、图标按 macOS 规范重做

生成脚本 `assets/make-icons.py`（PIL），母图与托盘图一次生成，可复现。

### 3.1 应用图标：HIG 栅格

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 画布 | 1024 × 1024 | macOS 图标母图标准尺寸 |
| 图形区 | 824 × 824，四周各留 100 | HIG 的呼吸边距 |
| 圆角半径 | 185 | 即 824 × 22.4%，squircle 近似 |
| 外部 | 全透明 | 系统自己合成形状 |
| 阴影 | **不烤进图里** | 系统会按当前外观自行投影，烤进去会双层阴影 |

构图与配色：

- 底：竖向渐变圆角方形，`#3D8BFD`（顶）→ `#1D65D8`（底），逐行插值填色后用圆角遮罩裁切。
- 文件夹：白色背板 `[216,262,808,648]` + 左上标签页 `[216,216,470,300]`，前板
  `[216,318,808,648]` 用 `#E8F1FD` 微偏蓝，露出折痕。
- 路径胶囊：白色 `[176,690,848,806]`，内部三段 `110×44` 圆角块（`#1D65D8`）代表路径片段，
  块间 24px 间隙，两个 13px 粗、`joint="curve"` 的折线箭头作分隔符 —— 呼应「路径」这一功能。

产出链：

```bash
python3 assets/make-icons.py                    # → icon-source.png / icon-512.png / tray-template@2x.png
cargo tauri icon assets/icon-source.png         # → src-tauri/icons/*（含 icon.icns）
```

`cargo tauri icon` 会连带生成 `icons/android/`、`icons/ios/`，本项目只有 macOS，已删除。
`icons/` 下仍保留 `icon.ico` 与 `Square*.png` 等 Windows 尺寸 —— 是 tauri-cli 的固定产物，
macOS 打包不读取，留着以免下次生成时又出现差异。

### 3.2 菜单栏图标：模板图

- `assets/tray-template@2x.png`，36 × 36，**纯黑描边 + 透明背景**（文件夹轮廓 + 左上标签 + 底部短横）。
- 配合 `TrayIconBuilder::icon_as_template(true)`，由系统在深色/浅色菜单栏下自动反色。
  全彩图标在其中一种外观下会看不清。
- 这里**不需要** `*Template.png` 的文件名约定 —— 那是 `NSImage imageNamed:` 的路径规则，
  本项目走 `include_image!` + `icon_as_template`。
- 实测渲染：菜单项几何 `1276,3,20,24`，截图放大确认图标完整未裁切。

## 四、版本号显示

单一真源是 `src-tauri/tauri.conf.json` 的 `version`，三处消费，没有任何一处写死：

| 消费点 | 实现 |
| --- | --- |
| 托盘菜单底部「版本 1.0.0」 | `MenuItem::with_id(app, "version", format!("版本 {}", app.package_info().version), false, None::<&str>)` —— 第 4 参 `false` 即禁用态，呈灰色不可点 |
| `Info.plist` 的 `CFBundleShortVersionString` / `CFBundleVersion` | `build-app.sh` 用 `sed` 从 `tauri.conf.json` 取出 `VERSION`，再 `plutil -insert` 写入 |
| dmg 文件名 | `CopyPath_${VERSION}_universal.dmg` |

菜单顺序（实测）：`立即获取文件夹路径 / 复制选中项自身路径 / ─ / 最近路径 / ─ / 开机自启 / 退出 CopyPath / 版本 1.0.0`。

## 五、dmg 打包

### 5.1 为什么不用 `cargo tauri build --bundles dmg`

本机 `ld` 在链 `tauri_macros` 时稳定产出 LINKEDIT 字符串池未对齐的 dylib（rustc 报
`can't find crate`），`cargo tauri build` 要多编一遍这个 crate 因而走不通。本项目无前端、无窗口，
bundler 干的活（合并 Info.plist、塞 .icns）用几条 `cp`/`plutil` 就能等价完成，dmg 直接交给 `hdiutil`。
代价是 `Info.plist` 必须自给自足（不再依赖 Tauri 构建期合并），且版本号要手工 `plutil -insert`。

### 5.2 打包流程（`build-app.sh`）

```
cargo build --release --bin copypath        # 带坏 dylib 自动重链重试（最多 8 次）
  ↓ 手工组装 .app：二进制 / icon.icns / PkgInfo / Info.plist(binary1) + 版本键
codesign --force --deep --sign - --identifier com.lilin.folderpath
  ↓ 自检：LSUIElement=true、CFBundleIdentifier、CFBundleExecutable、codesign --verify --strict
hdiutil create -format UDZO                 # 卷内：CopyPath.app + Applications → /Applications 软链
  ↓ pkill 旧实例 → 装到 ~/Applications → open 启动
```

构建前的两条保护：`pgrep -f "[c]argo build"` 拒绝并发构建（同 target 目录会互相写坏产物）；
`INSTALL_DIR` 不等于 `~/Applications` 时直接报错退出。

### 5.3 输出目录：本轮变更

`$PROJECT_DIR/release/` → **`$HOME/Downloads/`**。仓库目录不再残留安装包。

### 5.4 签名：一条不能照办的说明

需求是「dmg 不需要签名，本机安装」。分两层：

- **dmg 层**：确实不需要，本来也没做 —— 无开发者证书签名、无公证。
- **`.app` 层的 `codesign --sign -` 保留**。它不是分发签名而是**运行前提**：Apple Silicon 上
  未签名二进制会被内核直接 SIGKILL。实测证据 —— 复制产物、`codesign --remove-signature` 后运行：

  ```
  $ ./sigtest-bin --probe folder; echo "exit=$?"
  exit=137
  ```

  删掉这一步只会得到一个打不开的应用。

### 5.5 Gatekeeper：README 的一处纠错

原文档称「首次打开会被拦，需右键 → 打开」。实测本机生成的 dmg 与装好的 `.app`
都**只有** `com.apple.provenance`，没有 `com.apple.quarantine` 隔离属性，双击即可运行。
已更正为：本机直接双击；只有经浏览器下载或隔空投送转到别的机器时才需要右键 → 打开。

### 6.2 只能由使用者确认的两项

1. **全局快捷键 ⌃⌥⌘P。** 注册返回成功，但本机合成键盘事件不投递给任何应用（对照组 ⌘Space、
   ⌘⇧3、⌘A 同样无效，而 CGEvent 合成**鼠标**点击有效），因此无法自动化验证。需真人按一次。
   该快捷键走 Carbon `RegisterEventHotKey`，不涉及辅助功能/输入监控权限。
2. **「有选中项」时的路径语义。** 访达的 `selection` 无法脚本写入（`set selection` 报 -10006），
   需在访达里选中文件/文件夹后，分别点一次两个菜单项，核对：选文件夹 → 复制该文件夹本身；
   选文件 → 「立即获取文件夹路径」给所在目录、「复制选中项自身路径」给文件自身。
