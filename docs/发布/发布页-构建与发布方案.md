# 发布页 · 构建与发布方案

> 适用版本：CopyPath 1.3.0　|　页面：根目录 `index.html`　|　线上：<https://andli0626.github.io/tools-folderpath/>
> 更新日期：2026-11-19　|　托管：GitHub Pages（`main` 分支 / 根目录）

本文说明发布页从设计、实现到上线、发版、回滚的完整方案。页面用法与产品功能以根目录
[README.md](../../README.md) 为准；带版本的交付记录见 [发布目录](./README.md)。

## 一、结论速览

| 项 | 做法 |
| --- | --- |
| 交付形态 | 单个自包含 `index.html`，样式与脚本内联，无构建步骤 |
| 外部依赖 | 零。字体走系统栈、图标内联 SVG、无统计、无 CDN |
| 下载 | 四个安装包放进仓库 `downloads/`，按钮用**相对路径** |
| 托管 | GitHub Pages，`main` 分支根目录，`.nojekyll` 跳过 Jekyll |
| 平台边界 | 仅 macOS 12.0+；Windows / Linux 明确不支持 |
| 维护成本 | 改一页、放一个包、跑一遍自检、推一次 |

一句话：**页面能不能开，取决于你引了什么，而不是你在哪托管。** 所以整站做成"自包含"，
不赌网络通畅。

## 三、页面信息架构

页面是单页长滚动，区块用 `id` 做锚点。顶栏导航只指向其中六个，实际内容如下：

| 区块 | 锚点 | 内容 | 事实来源 |
| --- | --- | --- | --- |

| 核心能力 | `#features` | 四种触发、路径语义、失败不写剪贴板、原生实现 | README「功能一览」 |
| 触发方式 | `#triggers` | 快捷键 / 托盘 / 工具栏 / 悬浮按钮四张卡，附"左键为何不直接复制" | README「用法」 |
| 路径语义 | `#semantics` | 6 种访达状态的语义表 | README「路径语义」、`finder.rs` |
| 安装 | `#install` | 三步安装 + 装到内部盘、开机自启、卸载 | README「安装」「卸载」 |
| 使用手册 | `#manual` | 安装授权 / 悬浮按钮 / 工具栏 / 卸载四张手册卡 | README、安装指南 |
| 版本更新 | `#updates` | 1.3.0 亮点 + 1.2.1 / 1.2.0 / 1.1.5 / 1.0.0 时间线 | `docs/发布/` 变更记录 |
| 常见问题 | `#faq` | 9 条：Windows 支持、-1743、工具栏无反应、无窗口、快捷键、单实例、悬浮按钮、通知、多选顺序 | README「故障排查」 |
| 结尾 CTA | 无 | 下载按钮 + 三条保障 | — |
| 页脚 | 无 | 产品 / 使用 / 工程三列导航、源码与文档入口 | — |

### 3.1 内容纪律

1. **所有数字必须有出处**：版本号取自 `src-tauri/tauri.conf.json`，体积取自实际文件，
   日期取自变更记录，语义表取自 README 与 `finder.rs`。
2. **不写没实现的能力**：页面不承诺 Windows、不承诺自动更新、不承诺设置界面。
3. **不暴露内部信息**：不写内网仓库地址、客户名、未发布功能；对外源码入口只指向
   GitHub 公开仓库。
4. **改版不丢事实**：重做视觉时逐条对照本表核对，避免样式升级把平台限制、签名说明
   或校验和弄丢。
5. **平台限制必须显眼**：下载区提示条、平台卡、FAQ 三处至少保留两处。只写在 FAQ 里，
   等于大部分用户看不到。

## 四、视觉与前端实现

### 4.1 设计语言

以 Apple HIG 为参照，不使用第三方设计系统：

| 维度 | 取值 |
| --- | --- |
| 强调色 | Apple systemBlue：浅色 `#0071e3`，深色 `#0a84ff` |
| 中性色 | Apple 灰阶：`#1d1d1f` / `#6e6e73` / `#f5f5f7` |
| 圆角 | 26 / 20 / 12 / 8，成组使用 |
| 投影 | 近 / 中 / 远三层叠加，不用单层重投影 |
| 字体 | `-apple-system`、`SF Pro`、`PingFang SC` 系统栈 |
| 主题 | `color-scheme: light dark`，跟随系统，无手动切换 |

### 4.2 响应式断点

| 断点 | 主要变化 |
| --- | --- |
| ≤ 1020px | Hero 改单列，能力区 4 → 2 列，包结构与页脚改单列 |
| ≤ 820px | 导航收起，数据条 4 → 2×2，下载卡 / 手册 / 安装说明改单列 |
| ≤ 480px | 按钮满宽，隐藏示意区通知浮层，发布卡信息纵向排布 |

### 4.3 交互脚本（共 4 段，均为原生 JS）

| 模块 | 作用 | 失败兜底 |
| --- | --- | --- |
| 顶栏滚动态 | 滚动超过阈值加阴影 | 无（纯装饰） |
| 锚点高亮 | `IntersectionObserver` 标记当前区块 | 直接退出 |
| 进场动画 | `.reveal` 进入视口后显形 | 不支持 IO 或用户偏好减少动效时全部直接显示 |
| 复制 SHA-256 | `navigator.clipboard` 写入，按钮闪现「已复制」 | `execCommand` 兜底，仍失败则提示「复制失败」 |

打印样式单独处理：`.reveal` 强制可见、`section` 避免跨页断裂。

## 五、国内可访问性设计（决定性部分）

页面能否在国内直连打开，主要取决于引了什么。当前实现逐项排除了高风险依赖：

| 资源类型 | 当前做法 | 若反过来做 |
| --- | --- | --- |
| 字体 | 系统字体栈 | 引 `fonts.googleapis.com` → 长时间空白或字体回退 |
| 样式 | 内联 `<style>` | 引 jsDelivr / unpkg 的 CSS → CDN 被墙时整页变纯文本 |
| 脚本 | 内联 `<script>` | 引第三方库 → 脚本超时阻塞 `load` |
| 图标 | 内联 SVG | 引图标库 → 图标全部变方块 |
| 统计 | 完全没有 | 引 GA / 百度统计 → 阻塞且泄露访问数据 |
| 图片 | 同源 `assets/icon-512.png` | 图床或 GitHub 附件 → 图裂 |
| 下载 | 同源 `downloads/*.dmg|zip` | Release 附件 → `objects.githubusercontent.com` 常超时 |
| 外链 | 仅 GitHub 仓库，点击才跳转 | 嵌入外域 iframe / 视频 → 被拦截或加载失败 |

页面里唯一的绝对地址是 `https://github.com/andli0626/tools-folderpath`，它是
`<a href>` 外跳，不产生页面加载请求。SVG 的 `http://www.w3.org/2000/svg` 只是命名
空间声明，浏览器不会发起请求。

### 5.1 自检脚本

`scripts/check-site-deps.sh` 在仓库根目录执行，做三件事：

1. 扫描所有 HTML / CSS / JS 中的高风险域与路径（Google Fonts、jsDelivr、unpkg、
   cdnjs、GA、百度统计、`raw.githubusercontent.com`、`objects.githubusercontent.com`、
   `codeload.github.com`、`releases/download`、polyfill.io、staticfile、bootcdn）。
2. 检查 `index.html` 是否存在 Release 下载链接。
3. 检查 `.nojekyll` 是否存在，并列出 `downloads/` 里就绪的安装包。

退出码 0 才允许发布。这条检查的价值在于：**防止后续有人顺手加一个 CDN 或统计脚本，
把整页拖垮。**

## 六、下载与完整性

### 6.1 为什么放仓库，不用 Release

GitHub Release 的附件实际由 `objects.githubusercontent.com` 提供，这是国内失败率最高
的环节。把 dmg / zip 直接放进仓库，用相对路径引用，请求始终落在 `github.io` 这个可用
域名上，与页面同源、同连接池。

代价是仓库增大 21 MB，且公开仓库意味着安装包对全网可见。这两点在项目体量下可接受。

### 6.2 校验和

主发布卡展示 dmg 的 SHA-256，并提供一键复制：

```
71894c0088a2dad09902f3c9223ffef09e1c56b164abb0a297c34fd542f7e87e
```

校验方法（终端）：

```bash
shasum -a 256 CopyPath_1.3.0_universal.dmg
```

**发版时必须重新计算**。校验和与文件不一致，比没有校验和更糟。

### 6.3 版本与文件名的绑定

页面里的下载链接写死了 `CopyPath_1.3.0_*`。升级到 1.4.0 时，文件名与页面文案必须同步
修改，否则按钮 404。当前 `index.html` 中 `1.3.0` 出现 20 余处，用下面的命令一次看全：

```bash
grep -n '1\.3\.0' index.html
```

## 七、首次发布流程

### 7.1 前置条件

- 仓库为 **public**（免费账号的 Pages 只能发公开仓库）。
- 本机已登录 GitHub CLI，且令牌含 `repo` 权限：

  ```bash
  gh auth status        # 应显示 Logged in to github.com account <user>
  ```

- Pages 采用 **Deploy from a branch**，分支 `main`、目录 `/ (root)`，不使用 Actions 构建。

### 7.2 提交并推送

```bash
git add index.html .nojekyll downloads assets/icon-512.png scripts/check-site-deps.sh
git commit -m "docs: 更新发布页"
git push origin main
```

> **本机注意**：全局 git 配置里有一条
> `url.https://ghfast.top/https://github.com/.insteadof=https://github.com/`。
> 该加速域名不可用时会直接阻断推送/拉取。可临时绕开：
>
> ```bash
> GIT_CONFIG_GLOBAL=/dev/null git -c credential.helper='!gh auth git-credential' push origin main
> ```
>
> 长期方案是删除该全局规则，或在网络恢复后恢复使用。

### 7.3 开启 Pages（只做一次）

网页端：仓库 **Settings → Pages → Source = Deploy from a branch → main / (root) → Save**。

命令行（已登录 `gh` 时）：

```bash
curl -sS -X POST \
  -H "Authorization: Bearer $(gh auth token)" \
  -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  --data '{"source":{"branch":"main","path":"/"}}' \
  https://api.github.com/repos/andli0626/tools-folderpath/pages
```

返回 `201` 表示创建成功；`409` 表示已存在，不需要重复创建。

### 7.4 等待与确认

首次部署通常 1–10 分钟。轮询首页状态，直到返回 200：

```bash
for i in $(seq 1 20); do
  curl -s -o /dev/null -m 15 -w "%{http_code}\n" \
    https://andli0626.github.io/tools-folderpath/
  sleep 8
done
```

看到 200 后再用浏览器打开，先按 `Ctrl/⌘ + F5` 强刷一次，避免边缘缓存拿到旧页。

## 八、发版更新清单

以 1.3.0 → 1.4.0 为例，按顺序执行：

| 步骤 | 操作 | 验证 |
| --- | --- | --- |
| 1 | 改 `src-tauri/tauri.conf.json` 的 `version`（版本号单一真源） | `grep version src-tauri/tauri.conf.json` |
| 2 | 打包：`./build-app.sh` 或 `./scripts/package-macos.sh` | 四个产物生成 |
| 3 | 把四个文件复制进 `downloads/`，删掉旧版本文件 | `ls -l downloads` |
| 4 | 更新 `index.html` 的版本号、文件名、体积、发布日期 | `grep -n '1\.3\.0' index.html` 应无残留 |
| 5 | 重新计算 dmg 的 SHA-256，替换页面里的值与复制按钮的 `data-copy` | `shasum -a 256` 与页面值一致 |
| 6 | 更新「本次更新」摘要与 `#updates` 时间线 | 与 `docs/发布/v<版本>-变更记录.md` 一致 |
| 7 | 跑 `./scripts/check-site-deps.sh` | 退出码 0 |
| 8 | 提交并推送 `main` | `git log -1` |
| 9 | 等 Pages 重建，验证首页与四个下载链接 | 全部 200，字节数与实际一致 |

> 版本号、文件名、体积、校验和这四项最容易漏。漏一项的表现分别是：
> 页面显示旧版本、按钮 404、信息与实际不符、校验失败。

## 十、故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 首页 404 | `index.html` 不在根目录，或 Pages 分支/目录选错 | 核对 Settings → Pages |
| 页面能开、样式全丢 | 引了境外 CDN 的 CSS | 改回内联样式，跑自检脚本 |
| 一点下载就失败 | 包挂在 Release 上，或文件名与页面不一致 | 移入 `downloads/` 并改名对齐 |
| 下载 404 但文件存在 | 文件名大小写、版本号不一致 | `ls downloads` 与页面链接逐字比对 |
| 改了线上没变 | 边缘缓存 / 部署延迟 | 强刷；等 1–10 分钟；确认推送成功 |
| 下划线目录 404 | Jekyll 处理 | 确认根目录 `.nojekyll` 存在 |
| 部署失败 | 单次超过 10 分钟，或单文件过大 | 压缩素材、拆分文件 |
| 校验和不匹配 | 文件被替换但值没更新 | 重新计算并替换两处（展示 + `data-copy`） |
| 推送报 TLS / EOF | 跨境链路抖动 | 重试；或按 7.2 的绕开方式推送 |
| `gh` 报 unexpected EOF | 设备授权换取令牌时断流 | 重新 `gh auth login --web`，用新验证码 |

## 十一、风险与边界

| 风险 | 影响 | 说明 |
| --- | --- | --- |
| ISP 差异 | 同一时刻电信/联通/移动结果可能不同 | 移动宽带、部分企业专线失败率更高 |
| 企业 / 政务内网 | `github.io` 大概率直接不通 | 这类场景改为飞书知识库、内网 OSS 或国内托管 |
| 高峰波动 | TTFB 从 0.8s 涨到 3s+ | 页面本身无第三方等待，影响主要在首字节 |
| 无 SLA | 流量或构建超限时被限速或要求迁移 | 当前体量远低于限制 |
| 公开仓库 | 源码、文档、安装包全部可见 | 不要把内部客户名、未发布功能写进页面 |
| Pages 使用条款 | 禁止商用站点 / 电商 / SaaS | 内部工具说明页合规，对外售卖官网不合规 |
| 仓库体积 | 安装包入库使仓库增大约 21 MB | 每次发版可删除旧包，控制总量 |
| 平台边界 | 仅支持 macOS | 页面在下载区、平台卡与 FAQ 三处说明，避免误下 |

### 11.1 关于 Windows

CopyPath 不是"漏了 Windows 包"，而是实现层面只支持 macOS：

- 取路径依赖访达与 `osascript`；
- 悬浮按钮是 AppKit 的 `NSPanel`；
- 打包使用 `hdiutil` 生成 dmg，CI 只有 `macos-15` runner。

要支持 Windows，需要另写取路径与悬浮窗两套实现，属于独立工程。页面必须保持
"仅 macOS、不支持 Windows"的明确表述，不要让用户误以为有 Windows 版。

## 十二、回滚与替代托管

### 12.1 回滚

```bash
git revert <坏提交>
git push origin main
```

Pages 会在下一次构建后恢复。若页面完全不可用，可在 Settings → Pages 里
**Unpublish site** 临时下线，修好后重新开启。

### 12.2 替代托管

| 方案 | 国内速度 | 备案 | 适用 |
| --- | --- | --- | --- |
| GitHub Pages | 中等、有波动 | 不需要 | 对外分享、技术社区 |
| EdgeOne Pages（不含大陆区） | 一般 | 不需要 | 折中，免备案 |
| EdgeOne Pages（含大陆区） | 快 | **必须 ICP 备案** | 正式对外、要稳定 |
| 阿里云 OSS / 腾讯 COS | 很快 | 绑自有域名必须备案 | 企业官网 |
| 飞书知识库 / 内网 OSS | 快 | 不需要 | 内部同事、政务客户 |

"免费 + 国内高速 + 长期稳定"三者目前无法同时成立：免费方案要么境外、要么需备案。
这是政策约束，不是产品缺陷。

## 十三、后续可做

1. **CI 自动同步**：在 `.github/workflows/release.yml` 打包完成后，把资产复制到
   `downloads/`、替换页面版本号与校验和并提交，减少手工漏项。
2. **`checksums.txt`**：随包产出一份 SHA-256 清单，页面链接过去，避免单点抄写错误。
