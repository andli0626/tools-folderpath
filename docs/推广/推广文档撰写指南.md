# 推广文档撰写指南

本文以 [CopyPath 推广落地页](./index.html)（`docs/推广/index.html`）的实际产出过程为样本，
总结**如何为一个小工具编写推广文档**。适用于单文件静态落地页，方法论同样适用于其他形式的
对外宣传材料。

配套产物：落地页本身、根目录 [README.md](../../README.md)（面向开发者）、
[安装指南](../核心功能/访达工具栏按钮-安装指南.md)（面向深度用户）。三者视角不同，
写作规范也不同，见第一节。

## 一、先定视角：推广页不是 README

| 文档 | 读者 | 回答的问题 | 语言基调 |
| --- | --- | --- | --- |
| README | 开发者 / 维护者 | 怎么构建、数据在哪、出错怎么办 | 事实、完整、含内部细节 |
| 功能文档（docs/核心功能/） | 深度用户 | 某个功能怎么装、原理是什么 | 步骤化、可查证 |
| **推广页** | **潜在用户（第一次听说）** | **它对我有什么用、要不要装** | **利益导向、克制、零门槛** |

推广页的三条视角纪律：

1. **不出现内部实现词汇。** 落地页里不写 bundle id、`osascript`、单实例锁、
   `instance.lock`——用户不关心。这些留在 README。
2. **每个特性翻译成利益。** 不写「通过 osascript 读取访达」，写
   「按一个快捷键，当前文件夹路径就进了剪贴板」。
3. **诚实优先于华丽。** 推广页会被熟人点开，夸大一句就损失一分信任（见第三节）。

## 二、信息架构：六段式骨架

落地页的叙事顺序按「吸引 → 说服 → 消除顾虑 → 行动」组织：

```
1. Hero        一句话价值主张 + 两个 CTA + 版本/体积/隐私三个数字 + 开源地址
2. 功能        三种触发方式（快捷键 / 托盘 / 工具栏按钮），每种配场景文案
3. 路径语义    「复制的到底是哪个路径」对照表——这是本工具最大的认知疑虑，必须正面回答
4. 安装        4 步：获取 → 首次运行授权 → 工具栏按钮（可选）→ 验证
5. FAQ         折叠面板，收录真实被问过的问题
6. CTA band + footer   最后一次行动召唤；footer 放版本号、系统要求、开源地址
```

两条经验：

- **把「认知疑虑」当一等公民排进结构。** 路径类工具的用户最怕「复制出来的不是我想要的」，
  所以语义对照表紧跟功能介绍，而不是塞进 FAQ。
- **安装段必须包含"怎么验证装成功了"**（第 4 步）。只写安装不写验证的指南，用户卡住就流失。

## 三、事实纪律：只写验证过的，且能对上代码

推广页里的每个数字、每条声明都要能回答「出处是什么」：

| 页面元素 | 事实来源 | 错误示例（本项目真实踩过的） |
| --- | --- | --- |
| 版本号 1.1.5 | `tauri.conf.json` 的 `version` | 手写后忘记随版本更新 |
| 「~3.9 MB 安装包」 | `ls -l ~/Downloads/CopyPath_*.dmg` 实测 | 估算值直接写上去 |
| 「macOS 12+」 | `Info.plist` 的 `LSMinimumSystemVersion` | 想当然写 11+ |
| 「0 网络请求」 | 确认过无联网代码 | — |
| ~~「MIT 协议」~~ | **删掉了**——仓库没有 LICENSE 文件 | 模板惯性：落地页模板都写 license |
| ~~「0 外部依赖」~~ | **删掉了**——Rust 依赖几十个 crate | 把「无运行时依赖」夸成「无依赖」 |

规则：**没有出处支撑的声明，宁可删掉也不写**。初稿里那两条删掉的声明就是「模板语言」
未经核对混进来的典型。

## 四、技术形态：单文件静态页

推广页的交付形态刻意选择**一个 HTML 文件**，理由和约束：

- 双击即可本地预览，发微信/网盘就能传播，无需任何服务器或构建步骤。
- 所有 CSS 内联在 `<style>`，所有 JS 内联在 `<script>`，图片 base64 内嵌。
- 字体只用系统栈（`-apple-system` + `SF Mono`），不引外部字体——引了就违背「0 网络请求」。

### 4.1 设计系统先行

即使在单文件里，样式也必须先建 token 再写组件，不允许散落硬编码颜色：

```css
:root{
  --brand / --brand-deep        /* 品牌色，取自应用图标 #3D8BFD → #1D65D8 */
  --ink / --ink-2 / --ink-3     /* 三级文字灰度 */
  --surface / --surface-2       /* 两级背景 */
  --sp-1 … --sp-6               /* 间距刻度 */
  --r-s / --r-m / --r-l         /* 圆角刻度 */
}
```

- 颜色用 HSL 定义，深浅色模式各一套（`prefers-color-scheme`）。
- 组件（`.btn`、`.chip`、`.step`、`.code`）只引用 token，不写死值。
- 视觉参照系：Linear（深色克制）、Stripe（数字排版）。小工具页最忌花哨——
  它卖的是「安静好用」，页面气质必须一致。

### 4.2 视觉素材：真图标 + CSS 模拟窗口

没有截图工具就**不用截图**，用 CSS/SVG 画一个 macOS 访达窗口模拟（`.mock-win`）：
红绿灯按钮、侧栏、双栏文件列表、路径栏、工具栏按钮位、复制成功 toast。要点：

- **应用图标用真图**：把 `icon-source.png` 转 base64 内嵌，模拟窗口里的工具栏按钮、
  toast 图标、footer 都用它。假图标一眼假。
- 模拟的是「用户装好后会看到的画面」，比任何文案都有说服力。
- 注意元素遮挡：toast 最初盖住了工具栏按钮位，移到右下角后两张图才能同框。

### 4.3 交互最小集

推广页不需要框架，两样交互值得做：

1. **代码块「复制」按钮**：`navigator.clipboard.writeText` + `execCommand('copy')` 兜底，
   成功后按钮变「已复制 ✓」再复原。安装命令让人手敲是体验事故。
2. **锚点导航 + 平滑滚动**：nav 的「功能 / 安装 / FAQ」直达对应段。

其余一律不做。轮播、动画序列、暗色开关对落地页都是负资产。

## 五、开源地址的显示方式

本轮实践结论（地址：`http://192.168.0.200/lil/tools-folderpath`）：

- **显示完整地址本身，不只是「开源仓库」四个字。** 内网 GitLab 场景下用户需要能直接
  复制网址，hover 看 status bar 不够。
- 放三个位置，各司其职：
  | 位置 | 形式 | 作用 |
  | --- | --- | --- |
  | Hero 数字行下方 | 文字行「开源地址：`<完整 URL>`」，等宽字体 | 第一眼可见 |
  | 安装段代码块 | `git clone <URL>` 一行命令 | 可直接复制执行 |
  | Footer | 普通链接 | 页面底部的常规出口 |
- **不要做成第三个 Hero 按钮。** 实测两个 CTA 按钮 + 第三个会换行，孤零零掉第二行很难看；
  地址本身比「仓库」这个词信息量大，文字行更合适。

## 六、验证流程（发布前必做）

推广页也是产品，要按 UI 标准验证，不能写完就交：

1. **浏览器实测**，不用「心算渲染」。本地起 Chrome（chrome-devtools MCP 或手动打开
   `file://` 路径），1440px 宽度逐段截图检查。
2. **功能用脚本核**：
   - 链接：`evaluate_script` 枚举 `a[href]`，确认开源地址三处都在、拼写一致。
   - 复制按钮：点击后读系统剪贴板核对（macOS 用 `pbpaste`；**不要在页面脚本里调
     `navigator.clipboard.readText()`，会触发权限弹窗挂死调用**）。
3. **双模式检查**：切深浅色各截一轮，token 体系下这应该是免费的，不免费说明有硬编码色。
4. **文案三查**：版本号、体积、系统要求对照代码与实测输出（第三节表格）。

### 已知的自动化工具坑（本机实测）

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| browser-use MCP 视口 0×0 | 截图空白、布局判断全错 | 换 chrome-devtools MCP，且 `evaluate_script`/`resize_page` 必须带 `pageId` |
| `clipboard.readText()` 挂起 | evaluate 调用永不返回 | 验证写入用 `pbpaste`，验证读取不做 |
| `file://` 路径含中文 | 需 URL 编码 | 用编码后的路径导航 |

## 七、维护约定

- **发版即改页**：版本号、安装包名、体积出现在 Hero、安装段、footer 多处，改一处必须全文
  搜旧值（如 `1.1.5`、`CopyPath_1.1.5`）逐处更新。
- **对外副本要同步**：如果页面被复制到其他位置分发（如
  `/Volumes/SanDis1TB/WK/tools-folderpath/docs/推广/工具介绍.html`），源文件更新后立即
  `cp` 覆盖，并 `grep -c` 关键新增内容确认同步成功。
- **新事实文档先问归属**：内部原理进 `docs/核心功能/`，交付记录进 `docs/发布/`，
  只有「面向潜在用户」的内容才进推广页。三者内容不互抄，视角不同。

## 八、清单：从零写一份推广页

1. [ ] 读 README 与功能文档，列出**可验证事实清单**（版本、体积、系统要求、每个特性）
2. [ ] 按六段骨架写文案初稿，每条特性做一次「实现 → 利益」翻译
3. [ ] 删掉所有没有出处的声明
4. [ ] 建 token（色板取自应用图标），再写组件样式
5. [ ] 真图标 base64 内嵌；用 CSS 画产品运行画面
6. [ ] 实现复制按钮与锚点导航，仅此两样交互
7. [ ] 浏览器 1440px 逐段截图 + 脚本核链接 + `pbpaste` 核复制
8. [ ] 深浅色各验一轮
9. [ ] 登记到 `docs/README.md` 索引；若有分发副本，同步并核验
