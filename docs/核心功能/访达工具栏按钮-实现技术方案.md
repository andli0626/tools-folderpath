# 访达工具栏按钮 · 实现技术方案

> 当前事实文档：描述 CopyPath Toolbar.app（访达工具栏一键复制路径）这一功能的实现方式与
> 技术约束。功能于 v1.1.5 交付，交付过程见
> [v1.1.5 变更记录](../发布/v1.1.5-变更记录.md)；面向使用者的安装步骤见
> [安装指南](./访达工具栏按钮-安装指南.md)。

## 1. 功能定义

把一个名为 **CopyPath Toolbar.app** 的小应用拖进访达工具栏后，在任何访达窗口点击该按钮，
立即把「当前文件夹路径」写入系统剪贴板并弹一条原生通知——语义与全局快捷键 ⌃⌥⌘P、
托盘菜单「立即获取文件夹路径」完全一致（路径归一规则见根
[README.md 路径语义](../../README.md#路径语义)）。

设计原型是 Go2Claude 的 `Go2Claude Toolbar.app`（同机长期验证过的成熟模式）。

## 2. 总体架构

同一 Rust crate 编出**两个二进制、两个 .app 包**，共享解析与复制逻辑：

```
                         copypath_lib (src-tauri/src/lib.rs)
                 ┌──────────────┬────────────────┬───────────────┐
                 │ finder.rs    │ clipboard.rs   │ notify.rs     │
                 │ AppleScript  │ arboard        │ notify-rust   │
                 │ 解析+归一化   │ 写剪贴板        │ +mac-notif-sys│
                 └──────┬───────┴───────┬────────┴───────┬───────┘
                        │               │                │
        ┌───────────────┴───┐   ┌───────┴────────────────┴───┐
        │ bin: copypath     │   │ bin: copypath-toolbar      │
        │ 常驻托盘应用       │   │ 一次性 helper（9 行入口）    │
        │ 托盘/快捷键/历史/  │   │ toolbar_copy() → exit       │
        │ 单实例锁/自启      │   │ 无窗口/无锁/无托盘           │
        └───────────────────┘   └────────────────────────────┘
          CopyPath.app             CopyPath Toolbar.app
          com.lilin.folderpath     com.lilin.folderpath.toolbar
```

两条入口在 lib.rs 里收敛到同一个 `copy_and_notify()`，行为不会分叉：

| 入口 | 调用链 | 通知方式 |
| --- | --- | --- |
| 快捷键 / 托盘菜单 | `fetch_and_copy()` → 工作线程 `finder::resolve` → 主线程 `finish()` → `copy_and_notify(paths, false)` | 异步线程（防挂死主程序） |
| 工具栏按钮 | `toolbar_main.rs` → `toolbar_copy()` → `finder::resolve` → `copy_and_notify(paths, true)` | **同步等待**（见 5.3） |

## 3. 运行时序

```
用户点击工具栏按钮
  │  LaunchServices 按按钮绑定的路径启动 .app
  ▼
copypath-toolbar 进程起来（LSUIElement=true → 不进 Dock、不抢焦点）
  │  Finder 仍是前台应用 ⇒「前置窗口」就是触发它的那个窗口
  ▼
/usr/bin/osascript -e <SCRIPT>          ← finder.rs，与主程序逐字节同一份脚本
  │  每行输出 `kflag \t 选中项路径 \t 容器路径`
  ▼
parse(stdout, FolderPath)               ← 选文件夹取自身 / 选文件取所在目录 / 多选去重
  ▼
arboard 写剪贴板（多行 = 每路径一行）
  ▼
show_and_wait 原生通知（"已复制路径" / "已复制 N 个路径"）
  ▼
process::exit(0)                        ← 全程 <1s，无常驻
```

失败路径：无访达窗口 / 未授权 / osascript 异常 → 通知 + stderr 打日志，**不动剪贴板**，
exit 1。这条与主程序「失败不污染剪贴板」的约定一致。

## 4. 关键文件

| 文件 | 职责 |
| --- | --- |
| `src-tauri/src/toolbar_main.rs` | helper 入口：`notify::set_bundle("com.lilin.folderpath.toolbar")` → `toolbar_copy()` → exit |
| `src-tauri/src/lib.rs` | `copy_and_notify()`（共用复制+通知）、`toolbar_copy()`（helper 顶层编排） |
| `src-tauri/src/finder.rs` | AppleScript 与解析器，**未为本功能改动**，两入口共用 |
| `src-tauri/src/notify.rs` | 新增 `show_and_wait()`；`set_bundle()` 供 helper 声明通知归属 |
| `src-tauri/Info.toolbar.plist` | helper bundle 描述（独立 bundle id、LSUIElement、授权文案） |
| `src-tauri/Cargo.toml` | 显式 `[[bin]]` ×2（见 5.1 坑位） |
| `build-app.sh` | 一次构建产出/签名/装包两个 .app，dmg 卷内含两者 |

## 5. 技术要点与踩坑记录

### 5.1 Cargo 显式 `[[bin]]` 关闭自动发现

`Cargo.toml` 一旦显式声明任一 `[[bin]]`，`src/main.rs` 的自动发现即被关闭。两个 bin 必须
都写全，否则 `copypath` 主程序会静默消失、`cargo build --bin copypath` 直接报错。已留注释。

### 5.2 焦点模型：为什么点击能拿到"当前文件夹"

工具栏按钮本质是 LaunchServices 启动一个 .app。helper 是 `LSUIElement`，不创建窗口、
不调用 `activate`（AppleScript 里也刻意没有 `activate`），因此启动瞬间**前台应用仍是
Finder**，`target of front Finder window` 与 `selection` 读到的就是用户点击按钮时所在的
窗口状态。若 helper 任何一处抢了焦点，这条链就断了——这是本功能最核心的不变量。

### 5.3 短命进程的通知必须同步发

`notify::show()` 刻意走独立线程（历史上 mac-notification-sys 曾把主线程挂死）。但 helper
点完即退：异步线程还没发出通知，`process::exit` 就把整条通知丢了。故 `notify.rs` 拆出
`build()` 并新增 `show_and_wait()`，`toolbar_copy()` 的成功与失败路径都同步等待。

### 5.4 单实例锁天然不冲突

主程序的 `instance.lock` 只在 `copypath` bin 的 `main()` 里获取；helper 是独立二进制，
不碰锁、不建托盘，与主程序**并存且互不依赖**——主程序没跑时工具栏按钮照样工作。

### 5.5 bundle id 设计

helper 用独立的 `com.lilin.folderpath.toolbar`：

- 好处：LaunchServices/TCC/通知归属与主程序互不干扰；主程序升级重签不牵连 helper 授权。
- 代价：访达自动化权限要**单独授予一次**（首次点击弹窗）；ad-hoc 重打包会使该授权失效，
  重置命令 `tccutil reset AppleEvents com.lilin.folderpath.toolbar`。

### 5.6 工具栏按钮绑定的是"拖入那一刻的路径"

访达工具栏项记录源 .app 的绝对路径。升级后（`build-app.sh` 原地替换
`~/Applications/CopyPath Toolbar.app`）按钮通常仍有效；若指向了已不存在的旧路径，表现为
点击无反应——删掉旧按钮重新拖入即可。因此 helper **必须装在内部盘**（同主程序对
LaunchAgent 的约束），不要留在 `/Volumes/SanDis1TB` 外置盘上拖。

### 5.7 刻意不做的事

- **不写「最近路径」历史**：历史与托盘子菜单联动需要 `AppHandle`，一次性 helper 为此
  起 tauri 不值当。需要历史就用快捷键/托盘入口。
- **不提供「复制选中项自身路径」语义**：工具栏按钮只对应 folder 一种语义，保持单一动作；
  另一语义仍走托盘菜单。
- **不做 IPC 唤醒主程序**（方案 B 否决理由）：点击必须无条件有结果，不依赖主进程存活。

## 6. 打包与签名

`build-app.sh` 对 helper 的处理与主程序同级：

```
cargo build --release --bin copypath --bin copypath-toolbar   # 坏 dylib 自动重链重试
  ↓ 组装 "CopyPath Toolbar.app"：二进制 / icon.icns / PkgInfo / Info.toolbar.plist + 版本键
codesign --force --deep --sign - --identifier com.lilin.folderpath.toolbar
  ↓ 自检：LSUIElement=true、CFBundleIdentifier、CFBundleExecutable、codesign --verify --strict
dmg 卷内：CopyPath.app + CopyPath Toolbar.app + Applications → /Applications 软链
```

ad-hoc 签名同样是运行前提（Apple Silicon 未签名二进制直接 SIGKILL），不是分发签名。
helper .app 约 744K（linker 死代码剥离后不含 tauri 运行时开销）。

| 层 | 手段 | 覆盖点 |

验证时的对照基准取**路径栏末项**而非窗口标题（分栏视图下两者可能不同层）。

## 8. 已知限制

- 仅覆盖 folder 语义；不进最近历史（见 5.7）。
- 首次点击需授权访达自动化；ad-hoc 重打包后需 `tccutil reset` 重新授权。
- 无访达窗口时点击失败（有意为之，与主程序一致，不会静默给出桌面路径）。
- 冷启动约 <1s，比常驻应用的快捷键多一次进程启动开销。
