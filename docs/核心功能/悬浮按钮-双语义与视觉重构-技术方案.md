## 一、结论

悬浮按钮从「一枚只有一种语义的胶囊」改成「**三段分段控件**」：

```
┌──────────────────────────────┐
│  📁 文件夹   │  📄 文件    ×  │
└──────────────────────────────┘
```

- **左段** 点一下 = 复制**文件夹路径**（选中文件夹取自身，选中文件取其所在目录，无选中取当前窗口目录）
- **右段** 点一下 = 复制**文件路径**（只取文件本身，选中全是文件夹时回退当前窗口目录）
- **右端 ×** 保持 1.2.1 的关闭语义，不变
- 按住任意复制段拖动 = 移动按钮，松手落盘；右键菜单保留（多一条入口，不是唯一入口）

视觉上换掉现在的手绘半透明白胶囊，改用 **`NSVisualEffectView` 毛玻璃**——这是本次
「美化」的真正主因，理由见第二节第一条。

**需要你拍板的一处语义**（我已按推荐实现前提写好，见第五节）：右段「文件」在**选中文件夹**
时应该给什么。推荐给「回退到当前窗口目录」，而不是给文件夹路径（否则标签在说谎）。

## 二、现状诊断（带行号证据）

### 2.1 白半透明胶囊在浅色背景上等于隐形 —— 最严重

`float_button.rs:321-322`：

```rust
NSColor::colorWithWhite_alpha(0.10, 0.86).setFill();
NSColor::colorWithWhite_alpha(1.0, 0.22).setStroke();
```

填充是**白色** 10% 透明、描边是**白色** 22%、文字是 `NSColor::whiteColor()`
（`float_button.rs:185`）。而悬浮按钮是**浮在任意内容之上**的常驻窗口——访达白色
窗口、白色文档、浅色壁纸都会让它近乎消失。这是**已存在的缺陷**，不是新增按钮带来的。

根因：手绘颜色没有承载背景信息。修法不是把 alpha 调大（那样深色背景下就太亮），
而是交给系统材质：`NSVisualEffectView` + `.hudWindow`，系统在浅色底自动给浅色材质、
深色底给深色材质。

### 2.2 没有任何就地反馈

全仓没有 `NSTrackingArea`、没有 hover 态、没有按下态。v1.2.1 甚至明确否决过 hover
依赖的方案（`docs/发布/v1.2.1-变更记录.md:26`：「需要 tracking area、hover 状态机、
动画；触摸板用户难以触发」），于是干脆什么都不做。

代价：点下去屏幕没反应，用户只能等系统通知弹出来才知道成没成。

> **注意：这条否决理由仍然成立**，所以 hover 只用作「纯装饰性提亮」，**任何功能都
> 不许只存在于 hover 态**。两个复制段常驻可见、可点，不依赖 hover 才有。

### 2.3 两种语义藏在右键菜单里

`float_button.rs:462-465`：左键只有 `ItemPath` 一种（`mouseUp` 硬编码，
`float_button.rs:397`），`FolderPath` 只能在右键菜单里点。这正是本次要拆掉的。

### 2.4 按钮加宽会暴露一个现成漏洞

`frame_at`（`float_button.rs:254-264`）只判断「窗口与某块屏幕是否相交」，
相交就认。但按钮宽度将从 107pt 涨到约 163pt（见第四节）——**之前拖到屏幕右缘的
用户，一升级就会有一半按钮出屏**。

对比 `default_origin`（`float_button.rs:273-284`）反而是会算边距的。保存位置还原这条
路径漏了。这是**必做修复项**，不是可选优化。

## 三、视觉方案（苹果语言）

### 3.1 容器：三级降级链路（本版核心修订）

> **本节在 2026-10-06 第二轮修订。** 第一轮写的是 `NSVisualEffectView` +
> `.hudWindow`。核实 SDK 27.0 后推翻：`.hudWindow` 只是 10.14 的老材质，
> **不是 macOS 26/27 的 Liquid Glass**。用户要求「符合 macOS 27 的毛玻璃」，
> 正确目标是 `NSGlassEffectView`。

链路按系统版本从新到旧：

| 级别 | 系统 | 实现 | 说明 |
| --- | --- | --- | --- |
| **L1 首选** | macOS 26+ | `NSGlassEffectView`（`style = .regular`） | Apple 原生 Liquid Glass，折射 + 高光边缘 + 随交互变形 |
| **L2 兜底** | macOS 10.14–25 | `NSVisualEffectView` + `.hudWindow` | 经典 vibrancy，观感接近但无折射 |
| **L3 保底** | macOS 12–13 | 手绘半透明胶囊 | **必须是 L2 的观感，不是 1.2.1 的白半透明**——见 3.1.1 |

**为什么必须降级**：项目 `tauri.conf.json:25` 写死 `minimumSystemVersion: "12.0"`，
而 `NSGlassEffectView` 是 `API_AVAILABLE(macos(26.0))`。直接换上去等于把
12.0–25.9 的用户全部**打到崩溃**（unrecognized selector），这是不可接受的回归。

运行时判定：

```rust
// 不硬编版本号：直接问系统这个类在不在，26+ 才有
let glass_cls = objc2::runtime::AnyClass::get(c"NSGlassEffectView").is_some();
```

用类存在性而非版本号比较，是因为它对未来的 macOS 大版本也成立，且不需要维护
版本白名单。类不存在就走 L2。

### 3.1.1 L3 必须是「深色胶囊」，不能沿用现状白半透明

第一轮诊断出的缺陷（浅底对比度 1.2:1）**不能带到降级路径里**。若 L3 照抄
1.2.1 的 `white @ 0.10`，那么 12.0–13.9 的用户拿到的是同一个缺陷——只是换了个
系统版本，没解决问题。

L3 取 **`hsl(220 22% 16% / .92)` 深色实底 + 白字**：深色实底在任何壁纸上都保证
对比度达标（白字 vs `#1F2028` ≈ 14:1），代价是失去通透感。这是有意的取舍——
**可读性优先于通透**，且降级路径不该让用户拿到比现版本更差的东西。

### 3.1.2 `effectIsInteractive` 走 KVC 兜（macOS 27 专属）

`NSGlassEffectView.h:45` 有 `effectIsInteractive`（**`API_AVAILABLE(macos(27.0))`**），
打开后玻璃会自带 hover / 按下的官方形变反馈——正好替代 3.4 手写的三态。

但**当前依赖绑定里没有这个属性**：已核实 `objc2-app-kit` 0.3.2 的
`src/generated/NSGlassEffectView.rs` 只有 `contentView` / `cornerRadius` /
`tintColor` / `style`，无 `effectIsInteractive`（该属性 27.0 才发布，crate 生成时
尚未收录）。

不升级依赖即可绕过——用 KVC 直接设：

```rust
glass.setValue(&NSNumber::from_bool(true), forKey: c"effectIsInteractive");
```

**这是本方案最脆的一处**，已单列为走查项 W-45 ~ W-48。KVC 对未声明 selector
在某些系统版本上会静默失败（不抛错、只是没效果），所以必须有肉眼可判的验收项，
不能只看代码写没写。

### 3.1.3 `cornerRadius` 由玻璃自己管，别手绘圆角

`NSGlassEffectView` 自带 `cornerRadius` 属性（`NSGlassEffectView.h:31`），
且它会对内容做折射裁切。因此 L1 路径下**不能再走 3.2 的手绘圆角**，
`drawRect:` 在 L1 下应只画图标、分隔线与 ×，圆角完全交给玻璃。

这修正了第一轮的一处设计错误：第一轮让 `drawRect` 画圆角矩形 + 毛玻璃背景，
在 L1 下会出现「手绘圆角盖在玻璃圆角上」的错位（两者曲率算法不同，
高光边缘会露出来）。

### 3.2 容器（仅 L2/L3 适用）

| 项 | L2 取值 | 理由 |
| --- | --- | --- |
| 容器 | `NSVisualEffectView`，material `.hudWindow` | 10.14 起可用；`.hudWindow` 在浅色底上比 `.menu`/`.popover` 更实 |
| 混合模式 | `NSVisualEffectBlendingMode::WithinWindow` | 只与本窗口后方内容混合，不吃桌面壁纸整体色调 |
| 描边 | 1px `white @ 0.12` 内描边 | 浅色底上边缘会发散，1px 内描边是 Apple 的标准收口手法 |
| 投影 | 保留 `panel.setHasShadow(true)`（现 `float_button.rs:216`） | 走系统窗口阴影，**不扩画布**，见 3.3 |

L1 路径下这些都不需要——玻璃自带边缘高光与投影。

> **更正第一轮的一处措辞**：第一轮写「`.hudWindow` 是 macOS 上唯一在任意背景下
> 都保持可读分离度的材质」。核实后该说法**无依据**，已删除。`.hudWindow` 只是
> 本方案 L2 档的一个可用选择，不是唯一解。

### 3.2 形状：L1 交给玻璃，L2/L3 用 radius 10

现在 `radius = height / 2`（`float_button.rs:318`），全胶囊。宽度从 107 涨到 163 之后，
4.5:1 的全胶囊会变成一根「药丸」，和 macOS 原生控件（toolbar、segmented control）完全不像。

| 级别 | 圆角来源 |
| --- | --- |
| **L1** | `NSGlassEffectView.cornerRadius = 10`（**玻璃自带，不要手绘**） |
| L2/L3 | `drawRect` 手绘圆角矩形，`RADIUS = 10.0` |

三种级别统一用 **10pt** 而非全胶囊。这对齐 macOS 26+ 控件圆角量级，
也是本次「好看」目标下最关键的一处取舍：**不是把胶囊加宽，是换一种形状**。

### 3.3 不扩画布 = 不引入命中区陷阱

毛玻璃想要更足的存在感，直觉做法是把面板做大、让胶囊画在中间留出阴影余量。
**本方案否决这条路**，理由是硬的：面板一旦大于可见胶囊，多出来的透明区域会**吃掉
下面应用的点击**。

现在的 `hitTest:`（`float_button.rs:308-313`）对任何点都返回自身，不做形状判定——
面板等于胶囊时没问题，一旦面板大于胶囊就是 bug。所以：

- 面板尺寸**严格等于**可见胶囊，阴影交给系统窗口阴影（macOS 对 borderless 窗口的
  系统阴影画在 frame 之外且**不计入命中区**）
- 保持 `hitTest:` 无条件返回 self 的现状，**不引入**基于路径的命中判定

### 3.4 反馈：L1 交给系统，L2/L3 手写

| 状态 | L1（macOS 26+） | L2/L3 |
| --- | --- | --- |
| 默认 | 玻璃静态 | 两段透明底 |
| hover | **玻璃自带形变**（`effectIsInteractive = YES`） | 指针所在段底色 `white @ .10` |
| 按下 | **玻璃自带形变** | 所在段底色 `white @ .16` |
| **复制成功** | 图标换 `checkmark` + 底色闪 `systemGreen @ .22`，**700ms** | 同左 |

L1 的 hover/按下由 Liquid Glass 自己处理——这正是用原生控件而非手绘材质的收益：
交互反馈由系统保证随版本演进，不会落后。

成功态三档通用：眼睛还在按钮上时就能确认，不用等跳走的系统通知。
实现：`flash_zone: Cell<i8>`（-1 无 / 0 文件夹 / 1 文件）+ `flash_until: Cell<f64>`
（`NSDate` 时间戳），用 `NSTimer` 以 0.05s 间隔重绘，到点复原并使能关闭。
`NSTimer` 属 Foundation，**已在 `objc2-foundation = "0.3"` 默认 feature 内**
（已核实：默认集 168 项含 `NSTimer`），无需改依赖。

> **前提条件**：若 3.1.2 的 KVC 在本机静默失败（`effectIsInteractive` 没生效），
> L1 就退化成「无 hover 反馈」，此时**必须**让 3.4 的手写三态在 L1 下也生效，
> 作为兜底。走查项 W-46 专门盯这条。

## 四、尺寸与命中区

### 4.1 新常量（替换 `float_button.rs:32-43`）

```rust
const HEIGHT: f64      = 36.0;  // 原 34，两个图标 + 文字需要更多呼吸
const PAD_L: f64       = 12.0;  // 原 PADDING 14
const ICON: f64        = 14.0;  // 原 15
const GAP: f64         = 4.0;   // 原 5
const FONT_SIZE: f64   = 12.0;  // 原 12.5
const SEG_PAD_R: f64   = 10.0;  // 每段文字右侧到分隔线的留白
const DIVIDER_W: f64   = 0.5;
const DIVIDER_INSET: f64 = 10.0;// 分隔线上下内缩，不通高
const RADIUS: f64      = 10.0;  // 原 height/2
const CLOSE_GAP: f64   = 4.0;
const CLOSE_ZONE: f64  = 18.0;  // 原 16，段多了 × 需要更宽容的命中区
const CLOSE_PAD_R: f64 = 2.0;
```

### 4.2 宽度公式

```
PAD_L + ICON + GAP + 36(文件夹) + SEG_PAD_R + DIVIDER_W + SEG_PAD_R
      + ICON + GAP + 24(文件) + SEG_PAD_R + CLOSE_GAP + CLOSE_ZONE + CLOSE_PAD_R
= 12 + 14 + 4 + 36 + 10 + 0.5 + 10 + 14 + 4 + 24 + 10 + 4 + 18 + 2
= 162.5pt
```

对比现状 107pt（`float_button.rs:188-191` 公式），**加宽 55.5pt**。

### 4.3 三段命中区（x 自左缘，单位 pt，总宽 162.5）

| 区 | x 范围 | 点击行为 | 可拖动 |
| --- | --- | --- | --- |
| 0 文件夹 | `0 … 76.0` | `Mode::FolderPath` | 是 |
| 分隔线 | `76.0 … 76.5` | 无（0.5pt 缝隙） | 是 |
| 1 文件 | `76.5 … 138.5` | `Mode::FilePath`（新增） | 是 |
| 2 关闭 | `142.5 … 160.5` | `hide_and_disable` | **否** |

- 「× 区禁止拖动」是 1.2.1 已定的规则（`v1.2.1-变更记录.md:65-68`），**保留**
- 拖动阈值 `DRAG_THRESHOLD = 4.0`（`float_button.rs:41`）**保留**，全局生效：
  任一段按下后位移超 4pt 即转为拖动，不触发复制
- 判定改为 `zone_at(x) -> u8` 纯函数，**必须配单测**

## 五、语义定义（需要拍板的一处）

现有 `Mode` 只有两个变体（`finder.rs:41-46`），本次新增第三个：

| 访达状态 | 文件夹段（FolderPath，**已存在**） | 文件段（FilePath，**新增**） |
| --- | --- | --- |
| 无选中项 | 当前窗口目录 | 当前窗口目录 |
| 选中 1 个文件夹 | 该文件夹自身 | **回退当前窗口目录** ← 待拍板 |
| 选中 1 个文件 | 它所在的目录 | 该文件自身 |
| 选中同目录 3 个文件 | 该目录（去重成 1 行） | 3 行 |
| 选中 1 文件 + 1 文件夹 | 目录 + 文件夹（2 行） | 1 行（只要文件） |
| 选中 3 个文件夹（无文件） | 3 行 | **回退当前窗口目录** ← 待拍板 |

### 为什么不直接复用 `ItemPath`

`ItemPath`（`finder.rs:45`）语义是「一律取选中项自身」，**选中文件夹时返回的是文件夹
路径**。若拿它当「文件」段，用户选中一个文件夹点「文件」却拿到文件夹路径——**标签
在说谎**。这种「看起来测过了、其实语义没兑现」的 UI 比缺功能更糟。

**推荐：新增 `Mode::FilePath`**，只取 `kind == 'F'` 的记录（`finder.rs:22-23` 的脚本
**已经输出** `D`/`F` 标志位，数据现成），`parse` 加一个 `match` 分支即可，
**不碰 AppleScript、不碰权限、不碰通知**。同时让两段**永远不重复**：选中 1 个文件时，
左段给所在目录、右段给文件自身——正好是用户最常要的一对。

**备选（若你要更小改动面）**：右段直接用 `ItemPath`，标签改成「选中项」以免说谎。
改动面从「finder.rs 加 1 个变体 + 3 个单测」降到 0，但少一种能力。

## 七、风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **`effectIsInteractive` KVC 静默失败** | L1 丢失原生 hover 反馈，观感与设计稿不符 | 手写三态作为兜底始终生效（3.4 注）；走查 W-45~W-48 专项验 |
| **玻璃 API 在旧系统 unrecognized selector 崩溃** | 12.0–25.9 用户直接打不开 App | **类存在性判定** + L2/L3 降级（3.1）。这是本方案最高优先级的风险 |
| 玻璃自带 `cornerRadius` 与手绘圆角叠加 | 边缘高光错位、露边 | L1 下 `drawRect` **禁止**画圆角（3.1.3） |
| 按钮加宽后老位置出屏 | 升级即回归 | `frame_at` 加夹紧（**必做**，见 2.4） |
| 三态命中区算错 | 点错段 | `zone_at` 纯函数 + 单测覆盖 4 个边界值 |
| hover 在触摸板/触屏不可达 | 功能丢失 | hover 只做装饰，功能全在常驻段上（见 2.2） |
| 700ms flash 与连点冲突 | 状态错乱 | `fetch_and_copy` 已有 `busy` 重入保护（`lib.rs:38`），flash 只反映 UI 态不重复触发复制 |
